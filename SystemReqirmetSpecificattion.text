# System Requirements Specification (SRS)

## Doctor Appointment System Backend

## 1. Introduction

This backend system is a role-based hospital appointment management platform for **Admin**, **Doctor**, and **Patient** users. It supports:

* Doctor scheduling and shift allocation
* Online and offline appointment booking
* Slot locking and token generation
* Appointment lifecycle tracking
* Prescription management
* Revenue and reporting dashboards
* Audit logging and patient history

### Strict business rule

**Online and Offline consultations must use different doctors.**
A doctor must be assigned to only one consultation mode at a time for a given shift/day.

---

## 2. Scope

The backend will manage:

* Authentication and authorization
* Doctor, patient, and admin management
* Specialities

* Appointment booking

## 5. Functional Requirements

## 5.1 Authentication

* User registration and login
* JWT-based session management
* Role-based route protection
* Password hashing before storage

## 5.2 Doctor Management

* Admin can create, update, deactivate, and reactivate doctors
* Assign speciality and consultation mode
* Set consultation fee
* Store clinic address for offline mode
* Store video link rules for online appointments

## 5.3 Speciality Management

* Admin can create, update, delete, and list specialities

## 5.4 Shift Management

* Admin defines shifts such as:

  * Morning
  * Evening
  * Night
* Each shift contains:

  * date
  * start time
  * end time
  * consultation mode
  * assigned doctor
* A shift must be assigned to a doctor before slots can be generated

## 5.5 Slot and Token Management

* Generate slots within a shift using configured duration
* Assign token numbers sequentially
* Mark slot as available, booked, completed, cancelled, or no-show
* Use transactional locking to prevent double booking
* Slot must be reserved atomically during booking

## 5.6 Appointment Management

* Patients book available slots
* Appointment lifecycle:

  * pending
  * confirmed
  * completed
  * cancelled
  * no-show
* Admin can view all appointments
* Doctor can update appointment status for their own appointments only

## 5.7 Prescription Management

* Doctor adds:

  * diagnosis notes
  * medicines
  * follow-up instructions
* Timestamp should be auto-recorded
* Prescription visible to patient and admin

## 5.8 Reports

* Daily, weekly, monthly appointment counts
* Revenue by doctor
* Revenue by speciality
* Online vs offline appointment distribution
* Appointment completion rate
* Cancelled and no-show reports

## 5.9 Audit Logging

* Track important actions such as:

  * login/logout
  * doctor creation/update
  * shift creation
  * slot generation
  * appointment booking
  * appointment cancellation
  * prescription creation

---

## 6. Business Rules

1. A doctor can serve **only one consultation mode** per shift/day.
2. Online and offline shifts must never be assigned to the same doctor at the same time.
3. A slot can be booked by only one patient.
4. A slot becomes locked immediately when booking starts.
5. Booking must fail if the slot is already reserved or expired.
6. Patients can only view their own medical history.
7. Doctors can only view appointments assigned to them.
8. Admin has full access to all records.
9. Token numbers must be unique within a shift.
10. Appointment fees are based on the assigned doctor.
11. Offline appointments must show clinic address.
12. Online appointments must show secure video link only after booking.

## 9. Validation Rules

### Registration

* email must be unique
* password minimum length required
* role must be valid

### Doctor creation

* speciality must exist
* consultation mode must be valid
* fee must be numeric and non-negative

### Shift creation

* start time must be before end time
* date must be valid
* doctor must be active
* consultation mode must match assigned doctor mode

### Booking

* slot must belong to available shift
* slot must not be locked/booked
* patient cannot book overlapping appointments
* mode must match doctor mode
* token number must not conflict

---

## 10. Security Requirements

* JWT authentication
* Role-based authorization middleware
* Password hashing
* Input validation on every route
* Prevent SQL injection through Prisma
* Use transactions for booking and slot locking
* Access control for patient records
* Secure hidden video links for online appointments
* Audit logging for sensitive actions

## 13. Recommended Appointment Flow

1. Admin creates doctor
2. Admin assigns speciality and mode
3. Admin creates shift
4. Admin generates slots
5. Patient logs in
6. Patient filters doctors by mode/speciality
7. Patient selects slot
8. Booking transaction locks the slot
9. Appointment gets token number
10. Doctor sees booked appointment
11. Doctor confirms/completes/cancels
12. Doctor adds prescription
13. Admin monitors reports and revenue

---

## 14. Important Implementation Note for Slot Locking

To prevent double booking:

* Start a Prisma transaction
* Check slot status
* Update slot to `LOCKED`
* Create appointment
* Assign token
* Commit transaction only if all steps succeed

This is the core protection for concurrent bookings.
